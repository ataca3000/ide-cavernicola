# Security Policy

## Supported Versions

At this time, security support is provided only for the latest stable version of IDE Cavernícola.

| Version | Supported |
| ------- | --------- |
| main | ✅ Yes |
| All previous versions | ❌ No |

## Reporting a Vulnerability

The security of our users and contributors is a priority. If you discover a security vulnerability in IDE Cavernícola, we encourage you to report it responsibly.

### How to Report a Vulnerability

Please do NOT create a public GitHub Issue for security vulnerabilities that have not yet been fixed.

Instead, use one of the following methods:

- Open a private GitHub Security Advisory, if available.
- Contact the project maintainer directly.
- Use the contact method provided in the repository.

### Information to Include

To help us investigate and resolve the issue as quickly as possible, please include:

- A clear description of the vulnerability.
- Steps to reproduce the issue.
- The potential impact or security risk.
- Screenshots, logs, or proof-of-concept material if available.
- The affected version of IDE Cavernícola.
- Your operating system and environment details.

### Response Process

Once a report is received, we will:

1. Acknowledge receipt of the report.
2. Assess the severity and reproducibility of the issue.
3. Investigate and develop a fix when necessary.
4. Release a security update or mitigation.
5. Credit the reporter, if they wish to be acknowledged.

### Responsible Disclosure

We kindly ask that you do not publicly disclose the vulnerability until a fix or mitigation has been released. Responsible disclosure helps protect users and gives maintainers time to address the issue properly.

## Scope

This policy applies to:

- The official IDE Cavernícola source code.
- Project-maintained scripts and tools.
- Official releases distributed through this repository.

This policy does not apply to:

- Third-party modifications or forks.
- Custom deployments and configurations.
- External dependencies outside the project's direct control.

## Security Best Practices

Users are encouraged to:

- Keep their installation up to date.
- Review code before executing custom scripts.
- Avoid using untrusted third-party plugins or modifications.
- Report suspicious behavior or potential vulnerabilities promptly.

## Acknowledgments

We sincerely thank security researchers, contributors, and community members who help improve the security and reliability of IDE Cavernícola through responsible disclosure and constructive collaboration.
